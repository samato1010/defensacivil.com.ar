📅 Febrero 2026 🎯 Lanzamiento Oficial ⚡ 15 Mejoras Priorizadas

🎯 Visión General

DefensaCivil.com.ar es un recurso público que reúne contactos institucionales, historia y normativa del sistema de Defensa Civil en Argentina. Para el lanzamiento oficial necesitamos:

  • Seguridad primero: Separar datos públicos de credenciales privadas
  • Contenido completo: Ampliar directorio, agregar más normativa, publicar historia
  • UX pulida: Navegación clara, búsqueda funcional, responsive impecable
  • SEO y accesibilidad: Meta tags, alt text, estructura semántica
  • Performance: Optimización de imágenes, carga rápida, caché apropiado

🔴 Mejoras Críticas (Pre-lanzamiento)

Estas mejoras deben implementarse ANTES del lanzamiento oficial por razones de seguridad y funcionalidad básica.

Crítico 1. Separar Credenciales del JSON Público

Actualmente /data/colaboradores.json contiene hashes de contraseñas, IPs y user-agents accesibles públicamente.

Solución:
  • Crear /data/colaboradores_public.json solo con meta + collaborators[]
  • Mover items[] (credenciales) a /admin/_storage/colaboradores_items.json
  • Proteger /admin/_storage/ con .htaccess (Deny from all)
  • Actualizar scripts PHP para leer del storage privado
# /admin/_storage/.htaccess Order deny,allow Deny from all

Crítico 2. Agregar Páginas de Error Personalizadas

Actualmente errores 404/500 muestran páginas default del servidor.

  • Crear /404.html y /500.html con diseño consistente
  • Agregar directivas en /.htaccess
  • Incluir navegación de regreso al inicio

Crítico 3. Implementar CSRF Protection en Admin

Formularios admin sin protección CSRF - vulnerable a ataques.

  • Generar tokens CSRF en sesión PHP
  • Validar en cada POST/PUT/DELETE
  • Agregar campo oculto en todos los formularios admin

Alta 4. Mejorar Validación de Inputs

Sanitización básica pero inconsistente en endpoints PHP.

  • Validar tipos de datos (email, URL, teléfono)
  • Limitar longitud de campos
  • Escapar outputs en HTML
  • Usar prepared statements donde corresponda

Alta 5. Rate Limiting en Alta de Colaboradores

Sin límite de solicitudes - vulnerable a spam/abuso.

  • Máximo 3 solicitudes por IP por hora
  • Almacenar timestamps en archivo/sesión
  • Mensaje amigable cuando se excede el límite

📝 Mejoras de Contenido

Alta 6. Completar Directorio Nacional

Faltan entradas de múltiples provincias. Meta: al menos una entrada por provincia.

  • Prioridad 1: Buscar contactos en sitios .gob.ar oficiales
  • Prioridad 2: Contactar municipios/provincias directamente
  • Prioridad 3: Verificar datos existentes (teléfonos, emails)
  • Agregar campo "última verificación" en cada entrada

Media 7. Expandir Sección de Normativa

9 documentos actuales - agregar normativa provincial y decretos relevantes.

  • Buscar normativa provincial en BoRAs oficiales
  • Agregar resúmenes ejecutivos (2-3 párrafos)
  • Tags mejorados para búsqueda/filtrado
  • Links a PDFs oficiales cuando disponible

Media 8. Enriquecer Página Historia

Contenido base sólido - agregar línea de tiempo visual e imágenes históricas.

  • Crear timeline interactivo con hitos clave
  • Agregar imágenes históricas (optimizadas)
  • Referencias bibliográficas al pie
  • Botón "compartir en redes" para difusión

Media 9. Agregar Sección "Recursos"

Nueva página con materiales útiles para organismos de DC.

  • Guías y protocolos descargables
  • Templates de documentos
  • Links a cursos/capacitaciones
  • Material de difusión (infografías, posters)

Alta 10. Unificar CSS en Archivo Externo

Actualmente cada HTML tiene CSS inline - dificulta mantenimiento.

  • Crear /assets/css/main.css con todos los estilos
  • Mantener design tokens en :root
  • Incluir vía <link> en todas las páginas
  • Versionar para cache-busting: ?v=1.0.0

Alta 11. Implementar Búsqueda Funcional

Directorio.html necesita búsqueda/filtrado por provincia, municipio, nombre.

  • Barra de búsqueda sticky en top
  • Filtros por provincia (dropdown)
  • Búsqueda en tiempo real (JavaScript)
  • Resaltar términos encontrados
  • Contador de resultados

Media 12. Mejorar Responsive en Móviles

Algunas secciones no se adaptan bien en pantallas pequeñas.

  • Header: hamburger menu para navegación
  • Tablas: scroll horizontal con indicador visual
  • Cards: stack vertical en móvil
  • Touch targets mínimo 44x44px
  • Probar en iPhone SE, Galaxy, iPad

Media 13. Agregar Modo Oscuro (Opcional)

Feature opcional pero apreciada - especialmente para consultas nocturnas.

  • Toggle en header (guardar preferencia en localStorage)
  • CSS variables para colores dark
  • Respetar prefers-color-scheme del sistema

⚙️ Mejoras Técnicas

Alta 14. SEO y Meta Tags

Mejorar indexación y presentación en buscadores/redes sociales.

En cada página:
<!-- Meta tags básicos --> <meta name="description" content="..."> <meta name="keywords" content="defensa civil, protección civil, argentina"> <!-- Open Graph (Facebook) --> <meta property="og:title" content="..."> <meta property="og:description" content="..."> <meta property="og:image" content="..."> <!-- Twitter Card --> <meta name="twitter:card" content="summary_large_image">
Adicionales:
  • Crear /sitemap.xml y /robots.txt
  • Agregar JSON-LD para structured data
  • Canonical URLs en cada página

Media 15. Performance y Optimización

Mejorar tiempos de carga y experiencia del usuario.

  • Imágenes: WebP con fallback, lazy loading, dimensiones definidas
  • CSS: Minificar, eliminar unused, critical CSS inline
  • JavaScript: Defer/async, minificar
  • Caché: Headers apropiados en .htaccess
  • Gzip: Comprimir HTML/CSS/JS
# .htaccess - Compresión y Caché <IfModule mod_deflate.c> AddOutputFilterByType DEFLATE text/html text/css text/javascript </IfModule> <IfModule mod_expires.c> ExpiresActive On ExpiresByType text/css "access plus 1 month" ExpiresByType image/jpeg "access plus 1 year" </IfModule>

Semana 2: Contenido y SEO

Semana 3: Diseño y UX

• Unificar CSS en archivo externo
• Implementar búsqueda funcional

Semana 4: Performance y Lanzamiento
